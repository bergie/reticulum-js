# @reticulum/wasm-stamper

Fast WASM proof-of-work stamp engine for reticulum-js — the browser counterpart to `@reticulum/node`'s fast stamper.

## Why

`@reticulum/core`'s default stamp engine is pure WebCrypto, so it runs everywhere the library does. WebCrypto cannot clone hash state, and the LXMF proof-of-work stamp needs exactly that:

- Building the ~750 KiB memory-hard workblock costs three async WebCrypto calls per HKDF round. At the standard 3000 rounds that is ~15 000 `importKey`/`sign` round-trips, roughly a second of CPU per message.
- Searching for a stamp re-hashes the entire `workblock || stamp` buffer on every trial, because `crypto.subtle.digest` has no equivalent of `hash.copy()`. A stamp search at cost 16 (~65 000 expected trials) takes tens of seconds in a browser, mostly blocking the main thread.

This package installs an engine backed by [hash-wasm](https://github.com/Daninet/hash-wasm)'s hand-tuned WebAssembly SHA-256. WASM hashers can `save()` and `load()` their state, which is the capability WebCrypto lacks: the workblock is absorbed once, and each trial then hashes only the 32-byte stamp against the saved midstate.

## Usage

```js
import { useWasmStamper } from "@reticulum/wasm-stamper";

useWasmStamper();
// That's it — all @reticulum/core, @reticulum/lxmf and @reticulum/rfed
// stamping now runs on the fast engine.
```

Installing the engine is explicit and opt-in; importing `@reticulum/core` alone never changes stamping behavior. Call `setStamper(null)` (from `@reticulum/core/src/utils/stamper.js`) to switch back to the WebCrypto default.

## Performance

Measured on an Apple M-series laptop (Node's WebCrypto as the browser proxy — browsers show the same magnitudes):

| Operation | WebCrypto default | wasm-stamper | Node engine |
| --- | --- | --- | --- |
| Workblock build (3000 rounds) | ~950 ms | ~100 ms | ~60 ms |
| Stamp-search trial | ~800 µs | ~2.5 µs | ~3 µs |
| `generateStamp` cost 8 | ~1.0 s | ~90 ms | ~65 ms |
| `generateStamp` cost 16 | ~30–44 s | ~360 ms | ~95 ms |

The engine is hybrid: workblock build and stamp search run on WASM, yielding to the event loop whenever a synchronous stretch exceeds ~8 ms (a wall-clock budget, so the worst-case main-thread block stays about one half-frame regardless of device speed — measured at 8.7 ms over a 1.15-million-trial search), while one-shot hashing and validation stay on native `crypto.subtle`, which absorbs large workblocks faster than WASM — keeping message validation fast on receivers. The WASM yield channel is unref'd on Node/Bun, so the package never holds a server process open at exit. The Node engine additionally runs stamping in a worker thread and caches workblocks, so it remains the best choice where `node:crypto` is available.

## Compatibility

- Workblocks are byte-identical to the WebCrypto default engine and the Python `LXMF.LXStamper` reference.
- Stamp validity uses the same `SHA256(workblock || stamp) <= 2^(256 - targetCost)` boundary as every other engine; stamps generated by any engine validate under every other engine.
- The generation path never touches `crypto.subtle` (only `crypto.getRandomValues`), so stamping also works outside browser Secure Contexts.
